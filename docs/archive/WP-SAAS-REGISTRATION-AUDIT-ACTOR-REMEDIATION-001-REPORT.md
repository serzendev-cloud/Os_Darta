## Public Registration Audit Actor Attribution Remediation Report

==================================================
2. Root Cause
==================================================
During forensic discovery across the public registration flow:
1. `src/app/api/saas/register/route.ts` (lines 205–210) explicitly sent canonical actor metadata to `tenantProvisioningService.provisionTenant`:
   ```typescript
   {
     userId: 'system:public-registration',
     name: 'Public Self-Registration',
     role: 'public_guest',
   }
   ```
2. In `src/modules/saas/services/tenant-provisioning-service.ts`, `provisionTenant` accepted `actor` of type `{ userId?: string; name?: string; role?: string }` (line 74), and lines 357–358 correctly set:
   ```typescript
   actorId: actor.userId || 'system:super-admin',
   actorName: actor.name || 'Super Admin',
   ```
3. **DEFECT LOCATION**: On line 359 of `src/modules/saas/services/tenant-provisioning-service.ts`:
   ```typescript
   actorRole: 'super_admin', // <-- HARDCODED DEFECT
   ```
   The engine ignored `actor.role` provided by caller and unconditionally attributed `'super_admin'` as `actorRole` to the audit log event. Consequently, all audit logs generated by `provisionTenant`—regardless of whether triggered by Super Admin or Public Registration—were recorded in PostgreSQL with `user_role = 'super_admin'`.

4. Additionally, type definitions in `src/types/audit.ts` (`AuditLog.actorRole`) and `src/lib/db/services/auditLog.ts` (`AuditLogInput.actorRole`) constrained `actorRole` strictly to `UserRole` (which only contained tenant/internal user roles `admin | guru | santri | wali | super_admin`), causing type resistance against unprivileged actor representation like `'public_guest'`.

==================================================
3. Canonical Actor Model
==================================================
Analysis of codebase conventions confirmed:
- **Public Self-Registration Actor**:
  - `actorId`: `'system:public-registration'`
  - `actorName`: `'Public Self-Registration'`
  - `actorRole`: `'public_guest'` (Canonical non-admin representation already established in `src/app/api/saas/register/route.ts` and `src/types/auth.ts`)
- **Super Admin Provisioning Actor**:
  - `actorId`: `<super_admin_session_uid>`
  - `actorName`: `'Super Admin'`
  - `actorRole`: `'super_admin'`
- **PostgreSQL Column Compatibility**:
  - In `src/lib/db/schema.ts` (and live database `public.audit_logs`), column `user_role` is defined as `text('user_role')` (nullable text), natively accepting `'public_guest'` without requiring any migration or constraint alteration.

==================================================
4. Exact Fix
==================================================
1. **Dynamic Actor Role Propagation in Provisioning Engine** (`src/modules/saas/services/tenant-provisioning-service.ts`):
   Modified line 359 to propagate `actor.role` when supplied, falling back safely to `'super_admin'` only when omitted:
   ```typescript
   actorRole: (actor.role as any) || 'super_admin',
   ```

2. **Audit Contract Type Widening** (`src/types/audit.ts` & `src/lib/db/services/auditLog.ts`):
   Widened `actorRole` type signature from `UserRole` to `UserRole | string` in:
   - `src/types/audit.ts`: `AuditLog.actorRole: UserRole | string;`
   - `src/lib/db/services/auditLog.ts`: `AuditLogInput.actorRole: UserRole | string;`
   This allows canonical actor contexts (`public_guest`, `system`, etc.) to pass contract type validation while maintaining 100% backward compatibility for existing callers.

3. **Public Registration Security Guarantee** (`src/app/api/saas/register/route.ts`):
   Verified that `POST /api/saas/register` parses client payloads strictly through Zod schema `publicRegistrationSchema` which only accepts `{ name, slug, ownerName, ownerEmail, location, plan }`. Any client-injected `role`, `user_role`, `actorRole`, or `isSuperAdmin` fields are stripped server-side. The actor context passed to `provisionTenant` is permanently hardcoded server-side to `{ userId: 'system:public-registration', name: 'Public Self-Registration', role: 'public_guest' }`.
